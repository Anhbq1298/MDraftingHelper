# Build and debug

## Prerequisites

- Windows x64, AutoCAD 2021 (full, not LT). The managed assemblies used are `acmgd.dll`, `acdbmgd.dll`, `accoremgd.dll`, `AdWindows.dll` and `AcWindows.dll` from the AutoCAD 2021 install folder (or the ObjectARX 2021 `inc` folder).
- .NET SDK (any current SDK builds SDK-style `net48` projects) **and** the .NET Framework 4.8 targeting pack (Visual Studio 2019/2022 "NET Framework 4.8 targeting pack" or the Developer Pack).
- NuGet access for the test project only (xUnit).

This project does not use the .NET 8 `dotnet new civil` template from the Autodesk article: that template targets AutoCAD/Civil 3D 2025+. Its principles (one `IExtensionApplication`, explicit command classes, explicit Autodesk references with Copy Local off) are kept, on `net48`, with no Civil 3D references.

## Autodesk reference path

`src/MDraftingHeper.AutoCAD2021/MDraftingHeper.AutoCAD2021.csproj` references the Autodesk assemblies through `$(Acad2021Dir)` with `Private=false`; they are never copied to the output. Set it in one of these ways (first wins):

1. `dotnet build ... /p:Acad2021Dir="C:\Program Files\Autodesk\AutoCAD 2021"`
2. Environment variable `Acad2021Dir`
3. `Acad.user.props` at the repository root (git-ignored); copy `Acad.user.props.example`

The build fails with a clear message when the path is missing or wrong.

## Build

```powershell
dotnet build MDraftingHeper.sln -c Debug
dotnet test tests\MDraftingHeper.Core.Tests\MDraftingHeper.Core.Tests.csproj
.\tools\Build-Bundle.ps1                 # Release build + deploy\MDraftingHeper.bundle
```

`Build-Bundle.ps1` copies only `MDraftingHeper.*.dll` and the resources, refuses to continue if any Autodesk DLL appears in the output, and checks that the steel template DWG exists.

## Steel Dynamic Block templates

`assets/DynamicBlocks/MDH_SteelSections.dwg` is generated by AutoCAD itself; see [Dynamic-Block-Authoring.md](Dynamic-Block-Authoring.md).

```powershell
.\tools\DynamicBlocks\Build-DynamicBlocks.ps1 -Verify     # author + verify (opens AutoCAD windows)
.\tools\DynamicBlocks\Build-DynamicBlocks.ps1 -VerifyOnly # verify the committed DWG
```

## Debugging with NETLOAD

1. Build Debug. Output: `src\MDraftingHeper.AutoCAD2021\bin\Debug\net48\` (with a `Resources\` folder next to the DLL).
2. Start AutoCAD 2021 and run `NETLOAD`, choosing `MDraftingHeper.AutoCAD2021.dll`. If SECURELOAD warns that the folder is not trusted, choose *Load once* for development; do not lower SECURELOAD or add build folders to TRUSTEDPATHS globally.
3. To debug in Visual Studio: *Debug > Attach to Process > acad.exe* (managed code), or set `acad.exe` as the start program of the AutoCAD2021 project.

**DLL lock:** a loaded .NET assembly cannot be unloaded. Rebuilding while AutoCAD has it loaded fails with a locked-file error. Close AutoCAD, rebuild, and start again. Do not `NETLOAD` the Debug DLL while the bundle is also installed: two copies would register the same commands.

## Install / uninstall (per user)

```powershell
.\deploy\Install-MDraftingHeper.ps1     # copies the bundle to %APPDATA%\Autodesk\ApplicationPlugins
.\deploy\Uninstall-MDraftingHeper.ps1   # removes only MDraftingHeper.bundle (-RemoveUserData also removes settings/logs)
```

Both refuse to run while AutoCAD is open. `ApplicationPlugins` is a default trusted autoload location, so no security setting is changed. `PackageContents.xml` is gated to `SeriesMin=SeriesMax=R24.0` (AutoCAD 2021 only).

## Files at runtime

| What | Where |
| --- | --- |
| Settings (last-used options) | `%APPDATA%\MDraftingHeper\settings.json` (corrupt file → defaults) |
| User profile libraries | `%APPDATA%\MDraftingHeper\Profiles\*.json / *.csv` |
| Log | `%LOCALAPPDATA%\MDraftingHeper\logs\mdh.log` |

## Host tests

With the bundle installed and AutoCAD closed:

```powershell
.\tools\HostTest\Run-HostTests.ps1     # MDH_SELFTEST*, undo/redo, save + reopen (batch script)
.\tools\HostTest\Run-RibbonTest.ps1    # Ribbon startup, workspace switch, second drawing (COM)
.\tools\HostTest\Capture-Screens.ps1   # screenshots of Properties palette and dialogs
```

They open visible AutoCAD windows; do not type into them. `Capture-Screens.ps1` uses keystrokes for one Esc per dialog and is for screenshots only, not pass/fail evidence.

## Troubleshooting

| Symptom | Cause / action |
| --- | --- |
| Build: "Acad2021Dir is not set" | Set the property (see above). |
| No Ribbon tab | Check `mdh.log`. The tab is added when the Ribbon exists (on Idle) and again after a workspace change. Run `MDH_REBAR` from the command line to confirm the DLL loaded. |
| "Steel Dynamic Block templates are missing" | The bundle lacks `Contents\Resources\DynamicBlocks\MDH_SteelSections.dwg`; rebuild the bundle. |
| "Layer ... is locked" | Unlock the layer or change the layer name in settings. |
| Steel status "invalid" | A Properties value cannot be solved (e.g. t too large); AutoCAD keeps the last valid geometry. Enter a valid value or Undo. |
